# go-lessons

Интерактивный тренажёр Go в терминале: теория слева, код справа, проверка —
настоящий `go vet` и `go test`, а не мои слова.

## Установка и запуск

Нужен компилятор Go:

```sh
brew install go
go build -o go-lessons .
./go-lessons
```

Запуск без сборки, для разработки:

```sh
go run .
```

Рабочая папка создаётся сама в `~/go-lessons-practice`. Переопределить:
флаг `-workspace <путь>` или переменная `GO_LESSONS_WORKSPACE`.

## Клавиши

| | |
|---|---|
| `↑` `↓`, `j` `k` | выбор урока в списке, прокрутка в уроке |
| `Enter` | открыть урок |
| `r` | проверить: `go vet`, затем тесты |
| `tab` | править код в поле ввода (уроки-«сниппеты») |
| `e` | открыть папку урока в `$EDITOR` (проектные уроки) |
| `1` `2` | панель теории / панель проверки |
| `n` `p` | следующий и предыдущий урок |
| `Esc` | назад к списку |
| `q` | выход |

Прогресс лежит в `<рабочая папка>/.progress.json`. Его можно коммитить к себе
в репозиторий и переносить между машинами.

## Команды без интерфейса

```sh
./go-lessons list          # список уроков и прогресс
./go-lessons check 01      # проверить урок, код возврата 0 если сдан
```

`check` удобен в скриптах и в CI. Из рабочей папки можно проверить себя и вовсе
без тренажёра:

```sh
cd ~/go-lessons-practice && go test ./01-basics/
```

## Как устроено

```
main.go                    вход, вшитые уроки, команды list/check
internal/lesson            модель урока и раскладка файлов по рабочей папке
internal/runner            go vet / go test / go run, таймауты, убийство группы процессов
internal/progress          прогресс в JSON
internal/ui                интерфейс на Bubble Tea
testdata/lessons           уроки
testdata/solutions         эталонные решения — для теста «урок решаем»
scripts/pty-smoke.py       прогон в настоящем псевдотерминале
```

Уроки лежат в `testdata`, а не в `lessons`: `go build ./...` пропускает папки
с именем `testdata`, иначе заготовки уроков и их тесты пытались бы собраться
вместе с приложением.

## Как добавить урок

Каталог `testdata/lessons/NN-имя/` с четырьмя файлами:

```
meta.txt          title: Заголовок
                  kind: snippet | project
                  run: yes        — дополнительно выполнить go run
                  race: yes       — тесты с детектором гонок
lesson.md         теория в markdown
solution.go       заготовка, которую правит студент
solution_test.go  проверки
```

`kind: snippet` требует файл `solution.go` — он открывается в поле ввода
интерфейса. `kind: project` раскладывает файлы в рабочую папку, и студент
правит их своим редактором.

Потом добавьте эталонное решение в `testdata/solutions/NN-имя/` — без него
тест `TestEveryLessonIsSolvable` упадёт. Он для того и нужен: переписанный
тест урока очень легко сделать непроходимым, и заметить это на глаз нельзя.

## Тесты

```sh
go test ./...
```

Отдельно полезное:

```sh
# снимки экранов текстом — посмотреть глазами
DUMP_DIR=/tmp/shots go test ./internal/ui -run TestDumpScreen

# прогон в настоящем псевдотерминале
python3 scripts/pty-smoke.py
```

## Что стоит знать про проверку кода

Код студента выполняется по-настоящему, без песочницы. От бесконечного цикла
защищаемся так: команда уходит в собственную группу процессов, по таймауту
группа убивается целиком (`Setpgid` + `kill(-pgid)`), а `go test` получает
собственный `-timeout`, чтобы зависший тест завершился с дампом горутин, а не
висел вечно.

От записи не туда, куда надо, не защищаемся: рабочая папка ваша, код ваш.
Запускать тренажёр стоит под своим пользователем, а не от root.

## Известные ограничения

- Уроков три: это каркас, а не программа. Наполнение — отдельная и долгая работа.
- Поле ввода правит только `solution.go` в режиме `snippet`. Остальные файлы — внешним редактором.
- `textarea` показывает табы как четыре пробела. При сохранении код проходит через `gofmt`, так что на диске остаются правильные табы.
- Проверка идёт в одном модуле на все уроки: сломанный `go.mod` в рабочей папке сломает и проверку. Восстановление — удалить `go.mod`, тренажёр создаст новый.
