# go-lessons

Интерактивный тренажёр Go в терминале: теория, код и настоящая проверка
`go vet` + `go test`. Сам тренажёр ничего не редактирует — для этого есть
нормальный редактор.

## Установка и запуск

Нужен компилятор Go:

```sh
brew install go
go build -o go-lessons .
./go-lessons
```

Для разработки — `go run .`.

Рабочая папка создаётся сама в `~/go-lessons-practice`. Переопределить: флаг
`-workspace <путь>` или переменная `GO_LESSONS_WORKSPACE`.

## Клавиши

| | |
|---|---|
| `↑` `↓`, `j` `k` | выбор урока в списке, прокрутка активной панели |
| `Enter` | открыть урок |
| `r` | проверить: `go vet`, затем тесты |
| `tab`, `shift+tab` | переключить панель: теория → задание → проверка |
| `1` `2` `3` | прыжок к панели |
| `c` | открыть папку урока в VS Code |
| `g` | открыть VS Code на строке первой ошибки |
| `n` `p` | следующий и предыдущий урок |
| `Esc` | назад к списку |
| `q` | выход |

`r` работает из любой панели: поля ввода в интерфейсе нет, поэтому клавиши
никому не мешают. Активная панель подсвечена рамкой, и её имя подписано
внизу экрана.

## Рабочая папка

```
~/go-lessons-practice/
  .progress.json          прогресс — можно коммитить к себе в репозиторий
  lessons/
    01-basics/            самостоятельный Go-модуль
      go.mod
      tasks.go            это правит студент
      tasks_test.go       это проверки, их трогать не стоит
    02-slices/
      ...
```

Каждый урок — отдельный модуль (`module golessons/01-basics`). Это значит:

- VS Code открывает урок как самостоятельный проект, `code lessons/01-basics`;
- сломать один урок нельзя для остальных;
- проверить себя без тренажёра можно из папки урока: `cd lessons/01-basics && go test ./...`.

Обратная сторона: `go test ./...` из корня рабочей папки больше не покрывает
все уроки. Для этого есть `go-lessons check --all`.

## Команды без интерфейса

```sh
./go-lessons list          # список уроков и прогресс
./go-lessons check 01      # проверить урок, код возврата 0 если сдан
./go-lessons check --all   # все уроки
```

`check` печатает координаты ошибок (`tasks_test.go:16: ...`) и счётчик
прошедших проверок — удобно в скриптах и в CI.

## Как устроено

```
main.go                 вход, вшитые уроки, команды list / check
internal/lesson         модель урока и раскладка в рабочую папку
internal/runner         go vet / go test -json / go run, таймауты, убийство группы процессов
internal/progress       прогресс в JSON
internal/ui             интерфейс на Bubble Tea
testdata/lessons        уроки
testdata/solutions      эталонные решения — для теста «урок решаем»
scripts/pty-smoke.py    прогон в настоящем псевдотерминале
```

Проверка идёт в три шага и останавливается на первом провале: показывать
результаты тестов, когда код даже не собирается, бессмысленно.

Тесты запускаются с флагом `-json`. Разбор нужен ради двух вещей: счётчик
«сколько проверок прошло» вместо размытого «не сдано», и координаты
`файл:строка` для перехода редактором. Если разбор что-то не распознал,
сырой вывод остаётся на экране — молчание хуже.

Уроки лежат в `testdata`, а не в `lessons`: `go build ./...` пропускает папки
с именем `testdata`, иначе заготовки уроков и их тесты собирались бы вместе
с приложением.

## Как добавить урок

Каталог `testdata/lessons/NN-имя/`:

```
meta.txt          title: Заголовок
                  run: yes      — дополнительно выполнить go run
                  race: yes     — тесты с детектором гонок
lesson.md         теория в markdown
tasks.go          заготовка, которую правит студент
tasks_test.go     проверки
```

`go.mod` в исходниках урока не нужен — его создаёт раскладка в рабочую папку.
Причина измерена: `go:embed` пропускает каталог, в котором лежит `go.mod`,
и уроки перестали бы вшиваться в бинарник.

Потом добавьте эталонное решение в `testdata/solutions/NN-имя/tasks.go` — без
него упадёт тест `TestEveryLessonIsSolvable`. Он для того и нужен: переписать
проверки так, что задание не проходит ни у кого, очень легко, и на глаз это
не видно.

## Тесты

```sh
go test ./...
```

Плюс два инструмента, которые обычно нужнее юнит-тестов:

```sh
# снимки экранов текстом — посмотреть глазами или сравнить с прошлым
DUMP_DIR=/tmp/shots go test ./internal/ui -run TestDumpScreen

# прогон в настоящем псевдотерминале
python3 scripts/pty-smoke.py
```

## Что стоит знать про проверку кода

Код студента выполняется по-настоящему, без песочницы. От бесконечного цикла
защищаемся так: команда уходит в собственную группу процессов, по таймауту
группа убивается целиком (`Setpgid` + `kill(-pgid)`), а `go test` получает
собственный `-timeout`, чтобы зависший тест завершился с дампом горутин, а не
висел вечно. Тест `TestInfiniteLoopIsKilled` это проверяет.

От записи не туда, куда надо, не защищаемся: рабочая папка ваша, код ваш.
Запускать тренажёр стоит под своим пользователем, а не от root.

## Известные ограничения

- Уроков три: это каркас, а не программа. Наполнение — отдельная и долгая работа.
- Редактор внутри интерфейса намеренно не сделан. Пока был `textarea`, из него
  выросли два бага с клавишами, и стоил он дороже, чем польза.
- `c` и `g` рассчитывают на `code` из PATH. Если VS Code не установлен,
  используется `EDITOR`, а если нет и его — тренажёр честно говорит путь.
- Прогресс считает только последний прогон: «сдал, потом сломал» покажется как
  «сдан». История проверок не ведётся.
